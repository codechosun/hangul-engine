> **선행** · C++ 교재 `2.3` 함수 / `2.8` 클래스 기초 / `3.3` 연산자 오버로딩
> **만드는 것** · `lib/Matrix.hpp`, `lib/Nn.hpp` — 행렬, 층, 활성화 함수, softmax
> **예제** · C1-1 ~ C1-7

## 0. 세는 것에서 배우는 것으로

A파트와 B파트에서 만든 모델은 전부 **셌다.** `대한민국의 헌` 다음에 `법` 이 온다는 것을, 그 조합을 본 적이 있어서 안다.

한계는 A6에서 봤다. 6그램의 81%가 딱 한 번 나온 것이고, 조금만 다른 문맥이 오면 아무것도 모른다. B2에서 잰 최적 차수가 4였던 것도 같은 이야기다 — **더 멀리 보는 능력을 데이터가 못 받쳐준다.**

C파트부터는 다르게 간다. 글자마다 **벡터**를 하나씩 두고, 그 벡터들의 **계산 결과**로 답한다. 본 적 없는 조합이어도 비슷한 벡터를 가진 글자에서 배운 것이 적용된다.

이 장에서는 가장 작은 조각부터 만든다. 그리고 마지막에 **아직 아무것도 안 배운 망**이 얼마나 못하는지 재둔다. 그게 출발점이다.

```
[C1-7] 가중치를 아무렇게나 채운 망의 실력

  바이그램 2000개로 잰 평균 손실 = 8.6187
  퍼플렉서티 = 5534.4
  어휘 크기  = 5534
```

**5534에서 21까지 내려가는 것**이 C파트의 목표다.

## 1. 뉴런 하나

뉴런이 하는 일은 두 단계다.

```
1. 입력에 가중치를 곱해 더한다   s = w·x + b
2. 비선형 함수를 통과시킨다      y = f(s)
```

```cpp
FVector X(3);   X[0]=1;   X[1]=2;    X[2]=3;
FVector W(3);   W[0]=0.5; W[1]=-1;   W[2]=2;
Real Bias = 0.25;

Real Sum = (W * X) + Bias;
```

B3에서 만든 `operator*` 가 바로 여기서 쓰인다. **내적이 곧 뉴런의 첫 단계**다.

```
  x = (1, 2, 3), w = (0.5, -1, 2), b = 0.25
    w·x + b   = 4.750000   (손계산 4.75)
    tanh(...)  = 0.999850   (손계산 0.999850)
    relu(...)  = 4.750000   (손계산 4.75)
```

`0.5·1 + (-1)·2 + 2·3 + 0.25 = 4.75`. 손으로 확인된다.

**이 장의 모든 숫자는 손으로 확인된다.** C2에서 역전파를 만들 때 이 습관이 결정적이다. 순전파가 틀린 채로 역전파를 디버깅하면 영원히 못 찾는다.

## 2. 뉴런을 여러 개 늘어놓으면 행렬이 된다

뉴런 하나는 벡터 하나(`w`)를 갖는다. 뉴런을 여러 개 두면 벡터가 여러 개이고, 그것들을 줄로 쌓으면 **행렬**이다.

```
W = [ 0.5  -1   2 ]   <- 뉴런 1의 가중치
    [ 1     1   1 ]   <- 뉴런 2의 가중치
```

```cpp
FVector Y = Layer.Forward(X);   // W x + b
```

```
  Wx + b = (4.7500, 0.0000)
    손계산 (4.75, 0)
```

### 행렬의 모양을 어느 쪽으로 둘 것인가

```cpp
FLinear(size_t InSize, size_t OutSize) : Weight(OutSize, InSize), Bias(OutSize) {}
```

`W` 는 **(출력 × 입력)** 이다. 입력이 3, 출력이 2면 `2 × 3` 이다.

반대로 둘 수도 있다. 실제로 PyTorch의 `nn.Linear` 는 `(out, in)` 이고, 수식으로는 `y = xWᵀ + b` 라고 쓴다. 둘 중 하나를 고르고 **문서에 적고 끝까지 지키는 것**이 전부다.

우리가 `(출력 × 입력)` 을 고른 이유는 순전파가 자연스러워서다. 행렬의 한 줄이 뉴런 하나이고, 그 줄과 입력을 내적하면 그 뉴런의 출력이 나온다. **행 우선 저장에서 한 줄이 연속된 메모리**라 캐시에도 맞는다.

```cpp
const Real* Weights = M.RowData(Row);
double Sum = 0.0;
for (size_t Col = 0; Col < M.Cols(); Col++)
{
    Sum += (double)Weights[Col] * (double)V[Col];
}
```

### 첨자 계산을 클래스 안에 가둔다

```cpp
Real& operator()(size_t Row, size_t Col)
{
    return Values[Row * ColCount + Col];
}
```

이 한 줄이 `FMatrix` 의 존재 이유다. 밖으로 새면 어딘가에서 `Col * RowCount + Row` 로 쓰게 되고, **그 버그는 정사각 행렬에서 안 드러난다.** 테스트 행렬이 우연히 3×3이면 통과하고 실제 데이터의 5534×32에서 터진다.

D1의 `FTensor` 는 이걸 N차원으로 일반화한 것이다. 차원이 넷이 되면 첨자 계산이 `((n*C + c)*H + h)*W + w` 가 되고, 그걸 코드 곳곳에 흩뿌리는 것은 재앙이다.

### `operator()` 를 쓴 이유

`operator[]` 는 인자를 하나만 받는다. C++23 이전에는 `M[i][j]` 를 쓰려면 중간 프록시 객체를 만들어야 하는데 복잡하다.

`M(i, j)` 는 수학 표기 `M_ij` 와 닮았고 구현도 한 줄이다. Eigen, Armadillo 같은 실제 행렬 라이브러리가 전부 이 방식이다.

## 3. 비선형이 없으면 층을 쌓아도 소용없다

층을 둘 쌓으면 표현력이 늘 것 같다. 확인해보자.

```
W2(W1 x + b1) + b2 = (W2 W1) x + (W2 b1 + b2)
```

오른쪽은 **층 하나**다. 행렬 `W2W1` 과 치우침 `W2b1 + b2` 를 가진 층.

말로만 하지 말고 재보자.

```
[C1-3] 활성화 함수를 빼면 어떻게 되는가

  선형 층 두 개를 이어 붙인 것과, 그걸 하나로 합친 층을
  100가지 입력으로 비교했다. 최대 차이 = 4.768e-07
```

```cpp
CHECK((double)WorstGap < 1e-4);
```

**둘이 같다.** `4.768e-07` 은 `float` 의 반올림 오차다.

층을 백 개 쌓아도 결국 행렬 하나로 접힌다. **선형 변환의 합성은 선형 변환**이라는 선형대수의 기본 성질이다.

비선형 함수를 하나 끼우면 접히지 않는다.

```
  tanh 를 하나 끼우면 같은 입력에서 결과가 0.0539 만큼 달라진다
```

이게 **활성화 함수가 필요한 유일한 이유**다. "뇌의 뉴런이 발화하는 것을 흉내낸 것"이라는 설명을 자주 보는데, 실용적으로는 그냥 **접히지 않게 하려고** 넣는다.

## 4. tanh 와 relu

```
           x     tanh(x)     relu(x)
      -3.00   -0.995055    0.000000
      -1.00   -0.761594    0.000000
       0.00    0.000000    0.000000
       1.00    0.761594    1.000000
       3.00    0.995055    3.000000
```

`tanh` 는 무엇이 들어와도 `-1` 과 `1` 사이로 눌러 담는다. `relu` 는 음수만 0으로 만들고 양수는 그대로 둔다.

| | tanh | relu |
|---|---|---|
| 범위 | -1 ~ 1 | 0 ~ ∞ |
| 계산 | `exp` 두 번 | 비교 한 번 |
| 미분 | `1 - tanh²` | 0 또는 1 |
| 큰 입력에서 | 기울기가 0에 가까워진다 | 기울기가 그대로 1 |

마지막 줄이 C2에서 중요해진다. `tanh(3) = 0.995`, `tanh(4) = 0.9993` — 입력이 커질수록 **출력이 거의 안 변한다.** 미분하면 0에 가깝고, 역전파에서 그래디언트가 사라진다. 이것이 **기울기 소실**(vanishing gradient)이다.

`relu` 는 그 문제가 없어서 2010년대 이후 기본값이 됐다. 이 교재는 C3까지 `tanh` 를 쓰고(NPLM 원논문이 그랬다) D파트에서 현대적 선택으로 갈아탄다.

## 5. softmax — 점수를 확률로

출력 층이 내놓는 것은 점수다. `(2.0, 0.0)` 같은 숫자. 이걸 확률로 바꿔야 한다.

```
softmax(s)_i = exp(s_i) / Σ exp(s_j)
```

```
  softmax(1, 2, 3) = (0.0900, 0.2447, 0.6652)
    손계산 (0.090031, 0.244728, 0.665241)
    합 = 0.999999993
```

`e^1 : e^2 : e^3 = 2.718 : 7.389 : 20.086`, 합이 30.193. 나누면 위 숫자가 나온다.

### 성질 두 가지

**전부 같은 점수면 균등 분포다.**

```cpp
FVector Flat(4);                 // 전부 0
FVector FlatProbs = Softmax(Flat);
CHECK_NEAR(FlatProbs[i], 0.25, 1e-9);
```

C1-7에서 무작위 망의 퍼플렉서티가 어휘 크기와 같게 나오는 이유가 이것이다.

**점수 전체에 같은 값을 더해도 결과가 같다.**

```
  softmax(1, 2, 3)       = (0.0900, 0.2447, 0.6652)
  softmax(101, 102, 103) = (0.0900, 0.2447, 0.6652)
```

`exp(s+c) / Σexp(s+c) = e^c·exp(s) / (e^c·Σexp(s))` 이고 `e^c` 가 약분된다. **softmax는 점수의 절대값이 아니라 차이만 본다.**

### 그리고 이 성질이 구현을 구한다

```
  점수가 (800, 801, 802) 일 때
    그냥 exp 를 더하면 = inf  <- 넘쳤다
    최댓값을 빼고 하면 = (0.090031, 0.244728, 0.665241)
```

`exp(800)` 은 `double` 에서 무한대다. 그런데 **최댓값을 먼저 빼면** 지수가 전부 0 이하가 되어 절대 안 넘친다. 그리고 최댓값 항은 `exp(0) = 1` 이 되므로 분모가 0이 될 일도 없다.

```cpp
double Biggest = ...;                              // 최댓값을 찾는다
Exps[i] = std::exp((double)Scores[i] - Biggest);   // 빼고 exp
```

B2의 `LogSumExp` 와 **정확히 같은 요령**이다. 거기서는 로그합을 구하려고, 여기서는 넘침을 막으려고 썼을 뿐이다.

> D2의 어텐션에서 이 함수를 그대로 쓴다. 어텐션 점수는 `Q·K/√d` 인데, 차원이 크면 이 값이 쉽게 수십 수백이 된다. 최댓값을 안 빼면 **훈련 중반에 갑자기 `NaN` 이 뜬다.** 실제로 가장 자주 나오는 사고 중 하나다.

## 6. 손으로 따라갈 수 있는 망

입력 2, 숨은 층 2, 출력 2. 가중치를 손으로 채워 전체를 따라간다.

```
  x = (1, 0)
  Wx + b   = (1.0000, 1.0000)     손계산 (1, 1)
  relu     = (1.0000, 1.0000)
  출력 점수 = (2.0000, 0.0000)     손계산 (2, 0)
  softmax  = (0.8808, 0.1192)     손계산 (0.880797, 0.119203)
    정답이 0 번일 때 손실 = 0.126928  (손계산 0.126928)
```

마지막 줄의 **교차 엔트로피**가 C2의 주인공이다.

```cpp
Real CrossEntropy(const FVector& Probabilities, size_t Target)
{
    return (Real)(-std::log(P));
}
```

**정답에 준 확률의 음의 로그.** 확률 1이면 손실 0, 확률이 낮을수록 손실이 커진다.

B2의 퍼플렉서티와 같은 것이다. 퍼플렉서티는 `exp(평균 교차 엔트로피)` 다. **B파트에서 만든 자가 C파트에서 손실 함수가 된다.** 자와 목표가 같은 것이 이 분야의 편리한 점이다.

## 7. 출발점을 재둔다

가중치를 무작위로 채운 망에 실제 바이그램을 먹인다.

```
  입력 5534 -> 숨은 층 32 -> 출력 5534
  가중치 개수 = 354176 개
  바이그램 2000개로 잰 평균 손실 = 8.6187
  퍼플렉서티 = 5534.4
  어휘 크기  = 5534
```

```cpp
CHECK(Ppl > (double)Vocab * 0.5);
CHECK(Ppl < (double)Vocab * 2.0);
```

**퍼플렉서티가 어휘 크기와 같다.** 우연이 아니다.

무작위 가중치는 출력 점수를 거의 균등하게 만들고, 균등한 점수의 softmax는 균등 분포다. 균등 분포에서 정답의 확률은 `1/V` 이고, 교차 엔트로피는 `-log(1/V) = log(V)` 다. `log(5534) = 8.619` — 잰 값 `8.6187` 과 같다.

**훈련을 시작하기 전에 이 숫자부터 확인한다.** 실무에서 이걸 "초기 손실 확인"이라고 부른다.

- 어휘 크기 근처가 나오면 → 순전파와 초기화가 정상이다
- 훨씬 크면 → 가중치를 너무 크게 채웠거나 softmax가 틀렸다
- 훨씬 작으면 → 라벨이 새고 있다. 정답을 입력에 섞어 넣었을 가능성

**이 검사 하나가 반나절을 아껴준다.** 훈련을 몇 시간 돌리고 나서 "왜 손실이 안 내려가지"를 파는 것보다, 시작하기 전 1초에 잡는 게 낫다.

### 원핫 벡터는 낭비다

```cpp
FVector X(Vocab);                  // 5,534칸짜리 벡터
X[(size_t)IndexOf[Prev]] = Real(1);  // 그중 한 칸만 1
```

5,533개의 0과 하나의 1을 곱해서 더한다. **5,534번 곱셈 중 5,533번이 0을 곱하는 일**이다.

그런데 `W x` 에서 `x` 가 원핫이면 결과는 **`W` 의 한 열을 그대로 꺼낸 것**이다. 곱셈이 필요 없다. 그 열이 바로 그 글자의 **임베딩 벡터**다.

C3에서 이 최적화를 넣는다. 그리고 그때 임베딩이 별도의 개념이 아니라 **원핫 입력 층의 다른 이름**이라는 것이 드러난다.

## 정리

만든 것.

| 파일 | 내용 |
|---|---|
| `lib/Matrix.hpp` · `.cpp` | 행 우선 2차원 배열, 행렬-벡터 곱, 전치 곱 |
| `lib/Nn.hpp` · `.cpp` | `Tanh`, `Relu`, `Softmax`, `CrossEntropy`, `FLinear` |
| `lib/Random` | `RandomUnit`, `RandomRange` 추가 |

알아둘 것.

- **내적이 뉴런의 절반이다.** B3의 `operator*` 가 그대로 쓰인다
- **첨자 계산은 클래스 안에 가둔다.** 새면 정사각 행렬에서 안 드러나는 버그가 된다
- **선형 층을 쌓으면 접힌다.** 활성화 함수는 접히지 않게 하려고 넣는다
- **softmax는 점수의 차이만 본다.** 그래서 최댓값을 빼도 되고, 빼야 한다
- **교차 엔트로피 = 퍼플렉서티의 로그.** B파트의 자가 C파트의 손실이 된다
- **훈련 전에 초기 손실을 잰다.** `log(어휘 크기)` 가 나와야 정상이다
- **원핫 × 행렬 = 열 하나 꺼내기.** 그게 임베딩이다

쓴 문법.

- 클래스와 멤버 함수 — C++ 교재 `2.8`
- `operator()` 오버로딩 — C++ 교재 `3.3`
- `const` 오버로드로 읽기/쓰기 가르기

## 연습문제

**1.** `Softmax` 에서 최댓값 빼기를 없애고 C1-7을 돌리면 어떻게 되는가?

<details>
<summary>해답</summary>

**아무 일도 안 일어난다.** 그게 함정이다.

무작위로 초기화한 망의 출력 점수는 작다. `InitScaled` 가 `sqrt(1/InSize)` 범위로 채우므로 출력이 대략 `-1 ~ 1` 사이다. `exp(1)` 은 2.7이고 넘칠 이유가 없다.

문제는 **훈련을 시작한 뒤**에 온다. 가중치가 커지면 점수도 커지고, 어느 순간 `exp` 가 넘친다. 그러면 `inf / inf = NaN` 이 되고, `NaN` 은 역전파를 타고 **모든 가중치로 번진다.** 한 번 번지면 되돌릴 방법이 없어서 처음부터 다시 돌려야 한다.

그리고 이 사고는 **몇 시간 뒤에** 일어난다. 손실 그래프가 잘 내려가다가 갑자기 `nan` 이 찍히는 그 장면이다.

`NaN` 의 고약한 점을 하나 더 짚어두면, `NaN == NaN` 이 **거짓**이다. 그래서 `if (Loss == PreviousLoss)` 같은 검사로는 못 잡는다. `std::isnan(Loss)` 을 명시적으로 불러야 한다.

C3의 훈련 루프에 이 검사를 넣는다.

```cpp
if (std::isnan(Loss) || std::isinf(Loss)) { /* 여기서 멈춘다 */ }
```

**터질 수 있는 곳에 미리 검사를 걸어두는 것**이 훈련 코드에서 특히 중요하다. 추론은 틀리면 출력이 이상해져서 바로 보이지만, 훈련은 조용히 망가진다.

</details>

**2.** 숨은 층을 32에서 256으로 늘리면 초기 퍼플렉서티가 어떻게 되는가?

<details>
<summary>해답</summary>

**거의 안 바뀐다.** 여전히 5,534 근처다.

무작위 가중치는 어떤 크기든 균등에 가까운 출력을 내기 때문이다. 층이 넓어지면 **표현할 수 있는 함수의 종류**가 늘어나지만, 아직 아무것도 안 배웠으므로 그 능력이 쓰이지 않는다.

다만 완전히 똑같지는 않다. 숨은 층이 넓으면 출력 점수의 **분산**이 조금 달라지고, 그만큼 퍼플렉서티가 5,534에서 벗어난다. `InitScaled` 가 `sqrt(1/InSize)` 로 범위를 조절하는 것이 바로 이 분산을 맞추려는 것이다.

이 값을 어떻게 정하는지가 **초기화 전략**이라는 주제이고, Xavier 초기화·He 초기화 같은 이름이 붙어 있다. C3에서 다룬다.

바뀌는 것은 **가중치 개수**다. 32일 때 354,176개, 256일 때 2,833,408개. 8배다. 그리고 메모리도 8배, 계산 시간도 8배다. C5에서 이 계산을 빠르게 만드는 것이 주제가 된다.

</details>

**3.** `TransposedMultiply` 는 전치 행렬을 만들지 않는다. 만들면 무엇이 나빠지는가?

<details>
<summary>해답</summary>

셋이 나빠진다.

**메모리.** 5534×32 행렬의 전치는 32×5534이고, 같은 크기의 버퍼를 하나 더 잡아야 한다. 708KB다. 역전파에서 매 단계 이걸 하면 할당과 해제가 반복된다.

**캐시.** 전치를 만드는 것 자체가 캐시에 나쁘다. 원본을 행 방향으로 읽으면서 결과를 열 방향으로 쓰거나 그 반대다. 어느 쪽이든 한쪽은 **건너뛰며** 접근한다.

**할 필요가 없다.** 전치 행렬에 벡터를 곱하는 것은 **훑는 순서만 바꾸면** 되는 일이다.

```cpp
for (size_t Row = 0; Row < M.Rows(); Row++)
{
    const Real* Weights = M.RowData(Row);   // 원본 배치 그대로, 순차 접근
    double Scale = (double)V[Row];

    for (size_t Col = 0; Col < M.Cols(); Col++)
    {
        Sums[Col] += (double)Weights[Col] * Scale;
    }
}
```

원본을 한 줄씩 순서대로 읽으면서 결과에 누적한다. **원본 접근이 완전히 순차적**이다.

대가가 하나 있다. 결과를 누적해야 하므로 `Sums` 를 0으로 초기화하고 들고 있어야 한다. 일반 곱셈은 한 줄 끝나면 결과 한 칸이 확정되는데, 전치 곱셈은 **모든 줄을 다 봐야** 결과가 확정된다.

C5에서 이런 "같은 계산, 다른 순서"를 본격적으로 다룬다. 행렬 곱셈의 세 중첩 루프를 어떤 순서로 도느냐에 따라 속도가 **몇 배** 차이 난다.

</details>

## 다음 장

**C2. 로스와 수동 역전파.** ★

이 교재 전체에서 가장 중요한 장이다.

지금 우리 망은 가중치가 무작위다. 손실이 8.6187이고 퍼플렉서티가 5,534다. 이걸 낮추려면 **가중치를 어느 쪽으로 얼마나 움직여야 하는지** 알아야 한다.

그 답이 **그래디언트**다. 손실을 각 가중치로 미분한 값. 35만 개의 가중치 각각에 대해.

35만 번 미분하는 것이 아니다. **연쇄법칙**을 쓰면 순전파를 거꾸로 한 번 훑는 것으로 전부 나온다. 그 과정을 코드로 옮기는 것이 C2다.

그리고 **gradcheck** 를 만든다.

> 추론 버그는 출력이 쓰레기가 되어 **명백하다.**
> 훈련 버그는 손실이 *조금* 내려간다. **조용히 틀린다.**

수치미분으로 구한 값과 연쇄법칙으로 구한 값을 비교해서, 역전파가 맞는지 **증명**하는 도구다. 여기서 만들어두면 D파트 끝까지 쓴다. 이게 없으면 트랜스포머 디버깅은 불가능하다.

`Real` 을 `double` 로 바꾸는 `USE_DOUBLE` 스위치가 값을 하는 자리이기도 하다. `float` 에서는 수치미분의 오차가 너무 커서 통과인지 아닌지 판정이 안 된다.
