# D2. 어텐션 순전파

> **선행** · D1 (`FTensor`), C1 (softmax)
> **만드는 것** · `lib/Attention`
> **예제** · D2-1 ~ D2-6

---

## 0. 한 줄짜리 식

```
Attention(Q, K, V) = softmax(Q Kᵀ / √d) V
```

트랜스포머의 전부가 여기 있다. 네 단계다.

| | 하는 일 | 모양 |
|---|---|---|
| `Q Kᵀ` | 모든 위치가 모든 위치를 본다 | `(T, d) × (d, T)` → `(T, T)` |
| `/ √d` | 차원이 커지면 점수도 커진다. 눌러준다 | `(T, T)` |
| `softmax` | 점수를 확률로. 각 줄의 합이 1 | `(T, T)` |
| `× V` | 주목한 만큼 섞어 온다 | `(T, T) × (T, d)` → `(T, d)` |

```cpp
FTensor Scores = MatMul(Q, K.Transposed(2, 3));
for (i) Scores.At(i) *= 1 / sqrt(Dim);
if (bCausal) ApplyCausalMask(Scores);
SoftmaxLastAxis(Scores);
Result.Output = MatMul(Scores, V);
```

**다섯 줄이다.** D1에서 `FTensor` 를 만들어뒀기 때문에 식이 코드와 한 줄씩 대응한다. `FMatrix` 로 했으면 첨자 계산이 이 다섯 줄을 스무 줄로 만들었을 것이다.

## 1. 손으로 따라가기

```
  Q = [1 0; 0 1; 1 1], K 도 같다, V = [10 0; 0 10; 5 5]

  어텐션 가중치 (각 줄의 합이 1)
     0.40111 0.19778 0.40111   합 0.999999970
     0.19778 0.40111 0.40111   합 0.999999970
     0.24826 0.24826 0.50349   합 1.000000000

  출력
      6.0167   3.9833
      3.9833   6.0167
      5.0000   5.0000
```

첫 줄을 손으로 따라가보자. `Q` 의 첫 줄은 `(1, 0)` 이고, `K` 의 세 줄과 내적하면 `(1, 0, 1)` 이다. `√2` 로 나누면 `(0.7071, 0, 0.7071)`.

```
softmax(0.7071, 0, 0.7071) = (0.401112, 0.197776, 0.401112)
```

**정확히 맞는다.**

읽는 법이 보인다. `Q` 의 첫 줄 `(1,0)` 은 **`K` 의 첫 줄과 셋째 줄을 비슷하게 주목한다.** 둘 다 `(1,0)` 성분을 갖고 있기 때문이다. 그 결과 `V` 의 첫 줄 `(10,0)` 과 셋째 줄 `(5,5)` 를 40%씩, 둘째 줄 `(0,10)` 을 20% 섞어 `(6.02, 3.98)` 이 나온다.

**어텐션은 "닮은 것을 찾아 그 값을 가져오는 것"** 이다. 이름 그대로 주목이다.

세 번째 줄이 대각선에 가장 큰 값(0.50349)을 주는 것도 말이 된다. `Q` 의 셋째 줄 `(1,1)` 은 `K` 의 셋째 줄 `(1,1)` 과 가장 닮았다.

## 2. 검증 두 가지

### 각 줄의 합이 1

```
  줄 48개 전부에서 합이 1 인가. 최대 차이 = 2.980e-08
```

```cpp
CHECK(WorstGap < 1e-5);
```

softmax를 **마지막 축을 따라** 걸었으면 반드시 성립한다. 축을 잘못 골라 걸면 이 검사가 즉시 잡는다.

이게 중요한 이유가 있다. 축을 잘못 걸어도 **프로그램은 안 죽고 숫자도 그럴듯하다.** 훈련도 돌아간다 — 다만 모델이 아무것도 못 배운다. A0에서 말한 "조용히 틀리는" 것의 전형이다.

### 우상단이 0

```
  마스크를 걸면
      1.0000  0.0000  0.0000  0.0000  0.0000  0.0000
      0.4896  0.5104  0.0000  0.0000  0.0000  0.0000
      0.2430  0.3670  0.3900  0.0000  0.0000  0.0000
      0.2121  0.1524  0.3348  0.3007  0.0000  0.0000
      0.1196  0.2453  0.1577  0.1718  0.3056  0.0000
      0.3578  0.1798  0.1284  0.1157  0.0927  0.1257

  우상단의 최대값 = 0.000e+00 (0 이어야 한다)
  줄의 합은 여전히 1 인가. 최대 차이 = 7.451e-09
  첫 줄은 자기 자신만 본다 -> 1.000000000
```

**아래쪽 삼각형만 남는다.**

세 가지를 한꺼번에 확인한다.

```cpp
CHECK(WorstUpper < 1e-12);                          // 우상단이 0
CHECK(WorstGap < 1e-5);                             // 합은 여전히 1
CHECK_NEAR(Masked.Weights(0, 0, 0, 0), 1.0, 1e-9);  // 첫 줄은 자기만
```

세 번째가 특히 좋다. 첫 위치는 볼 수 있는 것이 자기 자신뿐이므로 **반드시 1.0** 이다. 마스크가 한 칸이라도 밀렸으면 여기가 깨진다.

그리고 네 번째 검사가 하나 더 있다.

```cpp
CHECK(OutputGap > 1e-3);   // 마스크가 출력을 **바꾸는가**
```

```
  마스크가 출력을 바꾸는가. 최대 차이 = 0.9355
```

**마스크를 걸었는데 출력이 안 바뀌면 안 걸린 것이다.** 마스크 코드를 썼는데 실수로 안 부르는 경우가 흔하다. "적용했으면 달라져야 한다"를 검사로 만들어두면 잡힌다.

### 마스크 값으로 `-무한대`를 안 쓴 이유

```cpp
const Real GMaskValue = (Real)(-1e30);
```

`-무한대`를 넣으면 한 줄이 통째로 막혔을 때 `exp` 가 전부 0이 되고, 분모가 0이 되어 **`0/0 = NaN`** 이 된다.

인과 마스크만 쓰면 자기 자신이 늘 열려 있어서 그럴 일이 없다. 그런데 **패딩 마스크**(길이가 다른 문장을 묶을 때)와 겹치면 실제로 생긴다. 유한한 값을 쓰면 최악의 경우에도 균등 분포가 나오지 `NaN` 은 안 된다.

B2에서 "무한대는 전염된다"고 한 것의 다른 얼굴이다.

## 3. 왜 `√d` 로 나누는가

이 나눗셈이 없으면 어떻게 되는지 재봤다.

```
[D2-4] 차원이 커지면 점수가 커진다

      차원   내적의 표준편차    나누기 전 엔트로피     나눈 뒤
         4             0.643                0.9334      0.9825
        16             1.318                0.7828      0.9816
        64             2.825                0.4455      0.9798
       256             5.161                0.2188      0.9829
      1024            10.638                0.0809      0.9807
```

**표준편차가 `√차원` 에 비례한다.** 4 → 16 → 64 → 256 → 1024로 네 배씩 늘릴 때마다 0.643 → 1.318 → 2.825 → 5.161 → 10.638, **약 두 배씩**이다.

이유는 간단하다. 독립인 항 `d` 개를 더하면 분산이 `d` 배가 되고 표준편차는 `√d` 배가 된다.

### 그래서 무슨 일이 생기는가

점수가 커지면 softmax가 **뾰족해진다.** 엔트로피(퍼진 정도)가 0.9334에서 **0.0809** 로 무너진다. 거의 한 곳만 1이고 나머지가 0이다.

그게 왜 나쁜가. **그래디언트가 안 흐른다.**

softmax의 미분은 `p_i(1 - p_i)` 꼴이다. `p` 가 0이나 1에 붙으면 이 값이 0에 수렴한다. C1에서 `tanh` 의 기울기 소실을 이야기했던 것과 같은 일이 여기서도 일어난다.

`√d` 로 나누면 **차원과 무관하게** 엔트로피가 0.98 근처로 유지된다. 표의 마지막 열이 그것이다.

> 이 나눗셈 하나가 트랜스포머 원논문의 제목(*Attention Is All You Need*)에 안 나오는 각주 하나에서 왔다. 빼먹으면 큰 모델이 학습을 시작조차 못 한다. **작은 상수 하나가 되느냐 안 되느냐를 가르는 자리**가 이 분야에 꽤 있다.

## 4. 헤드

```
[D2-5] 헤드를 나눴다 합치면 제자리인가

  (2, 6, 32) -> (2, 4, 6, 8) -> (2, 6, 32)
  왕복해서 제자리인가 = 예
  Split(b,h,t,d) == X(b,t,h*DIM+d) 인가 = 예
```

`(배치, 위치, 모델차원)` 을 `(배치, 헤드, 위치, 헤드차원)` 으로 나눈다.

```cpp
FTensor Reshaped = X.Reshaped({ Batch, Length, HeadCount, Head });
return Reshaped.Transposed(1, 2);
```

**두 단계다.** 모양을 바꾸고(공짜), 축을 바꾼다(값을 옮긴다). D1에서 두 연산의 비용이 다르다고 한 것이 여기서 값을 한다.

왕복 검사가 좋은 이유는 **두 함수가 서로를 검증**하기 때문이다. `SplitHeads` 와 `MergeHeads` 둘 다 맞거나 둘 다 같은 방식으로 틀려야 통과한다. 그래서 두 번째 검사를 따로 뒀다 — 자리를 직접 확인하는 것.

### 헤드가 여럿이면 무엇이 좋은가

```
  헤드 1개 -> 헤드당 차원 32, 출력 모양 (1, 6, 32)
  헤드 2개 -> 헤드당 차원 16, 출력 모양 (1, 6, 32)
  헤드 4개 -> 헤드당 차원 8,  출력 모양 (1, 6, 32)
  헤드 8개 -> 헤드당 차원 4,  출력 모양 (1, 6, 32)
```

**출력 크기가 같다.** 그리고 계산량도 거의 같다 — `(T×T×d)` 를 `H` 번 하는데 `d` 가 `H` 분의 1이니 곱하면 같다.

그럼 왜 나누는가. **하나의 어텐션은 한 가지 관계만 본다.**

`softmax` 를 한 번 걸면 확률 분포가 하나 나온다. 한 위치가 여러 곳을 동시에, 서로 다른 이유로 봐야 할 때 분포 하나로는 표현이 안 된다. 헤드를 여덟 개 두면 **여덟 개의 서로 다른 주목**을 동시에 할 수 있다.

실제로 훈련된 모델을 열어보면 헤드마다 역할이 갈린다. 바로 앞 단어를 보는 헤드, 문장의 첫 단어를 보는 헤드, 같은 단어가 앞에 나왔는지 보는 헤드. **D8에서 그중 하나를 직접 관측한다.**

## 정리

만든 것.

| 파일 | 내용 |
|---|---|
| `lib/Attention.hpp` · `.cpp` | 어텐션, 마지막 축 softmax, 인과 마스크, 헤드 나누기 |

알아둘 것.

- **어텐션은 닮은 것을 찾아 그 값을 가져오는 것**이다
- **각 줄의 합이 1**인지부터 확인한다. 축을 잘못 걸어도 안 죽는다
- **마스크를 걸면 출력이 달라져야 한다.** 안 달라지면 안 걸린 것
- **마스크 값은 유한하게.** `-무한대`는 `NaN` 을 부른다
- **`√d` 로 안 나누면 엔트로피가 무너진다.** 0.93 → 0.08
- **헤드는 계산량을 안 늘린다.** 관계를 몇 갈래로 볼지만 정한다
- **왕복 검사는 두 함수를 서로 검증한다.** 다만 같은 방식으로 틀리면 못 잡는다

쓴 문법.

- D1의 `Transposed`, `Reshaped`, `MatMul`
- 마지막 축을 따라 도는 관용구 (`Count() / Last` 로 줄 수 세기)

## 연습문제

**1.** `ApplyCausalMask` 에서 `for (k = q + 1; ...)` 를 `for (k = q; ...)` 로 바꾸면?

<details>
<summary>해답</summary>

**자기 자신도 막힌다.** 그러면 첫 줄은 볼 수 있는 곳이 하나도 없다.

모든 점수가 `-1e30` 이 되고, softmax는 전부 같은 값이므로 **균등 분포**를 돌려준다. `NaN` 은 안 나온다 — 마스크 값을 유한하게 둔 덕분이다.

그런데 **검사에는 걸린다.**

```cpp
CHECK_NEAR(Masked.Weights(0, 0, 0, 0), 1.0, 1e-9);
```

첫 줄의 첫 칸이 1.0이 아니라 `1/6 = 0.1667` 이 된다.

이 버그가 실제로 어떤 영향을 주는가. 각 위치가 **자기 자신을 못 본다.** 그러면 "현재 토큰이 무엇인가"라는 정보가 어텐션을 통과하지 못한다.

그래도 모델은 어느 정도 학습한다. 잔차 연결(D3)이 현재 토큰의 정보를 우회해서 전달하기 때문이다. **손실이 조금 나쁠 뿐 그럴듯하게 내려간다.** 다시 한 번, 조용히 틀리는 종류다.

그래서 `CHECK_NEAR(..., 1.0, ...)` 같은 **한 자리 검사**가 값을 한다. 전체 통계만 보면 안 보이는 것이 한 칸을 콕 집으면 보인다.

</details>

**2.** `√d` 대신 `d` 로 나누면 어떻게 되는가?

<details>
<summary>해답</summary>

**너무 눌러서 반대 문제가 생긴다.**

표준편차가 `√d` 에 비례하는데 `d` 로 나누면 `1/√d` 에 비례하게 된다. 차원이 커질수록 점수가 **0에 가까워진다.**

점수가 전부 0에 가까우면 softmax는 균등 분포를 돌려준다. 엔트로피가 1.0에 붙는다. 그러면 어텐션이 **아무것도 구별하지 않는다** — 모든 위치를 똑같이 본다.

훈련 초기에는 어차피 가중치가 무작위라 티가 안 난다. 문제는 **학습이 진행돼도 뾰족해지지 못한다**는 것이다. 점수를 키우려면 `Q` 와 `K` 의 가중치를 `√d` 배만큼 키워야 하는데, 그건 다른 부작용을 부른다.

일반화하면 이렇다. **정규화 상수는 "분산을 1로 만드는 값"이어야 한다.**

- `√d` 로 나누면 분산이 1 근처로 유지된다 — 맞다
- `d` 로 나누면 분산이 `1/d` — 너무 작다
- 안 나누면 분산이 `d` — 너무 크다

이 원리가 D3의 RMSNorm에서도, C3의 가중치 초기화(`sqrt(1/InSize)`)에서도 똑같이 나온다. **"분산을 1 근처로 유지한다"** 는 것이 신경망 설계 전반을 관통하는 규칙이다.

</details>

**3.** 어텐션의 계산량과 메모리는 문맥 길이에 대해 어떻게 늘어나는가?

<details>
<summary>해답</summary>

**둘 다 제곱으로 늘어난다.** 이게 트랜스포머의 가장 큰 약점이다.

`Q Kᵀ` 가 `(T, d) × (d, T)` 라 결과가 `(T, T)` 다. 문맥이 두 배가 되면,

- 계산량 `T² × d` → **네 배**
- 메모리 `T²` → **네 배**

`T = 1024` 면 어텐션 점수표 하나가 100만 칸이다. 헤드가 12개, 배치가 8이면 **1억 칸**, `float` 로 400MB다. 그리고 역전파를 위해 이걸 들고 있어야 한다.

이 제곱 항 때문에 나온 것들이 있다.

- **FlashAttention** — 점수표를 통째로 안 만들고 조각내 계산한다. 메모리가 `T` 에 비례하게 줄어든다. 계산량은 그대로
- **희소 어텐션** — 모든 위치가 모든 위치를 보지 않게 제한한다
- **선형 어텐션** — softmax를 근사해서 `T` 에 비례하게 만든다. 품질을 조금 내준다

우리 교재는 제곱 그대로 간다. 문맥이 짧기 때문이다(D7에서 128 정도). **문제가 안 되는 크기에서는 단순한 쪽이 낫다** — A4의 삭제 기능, C4의 포트란 순서와 같은 판단이다.

그런데 D4의 **KV 캐시**는 이 문제의 다른 얼굴을 다룬다. 생성할 때 글자를 하나씩 뽑는데, 매번 처음부터 다시 계산하면 `T` 글자를 만드는 데 `T³` 이 든다. 이미 계산한 `K` 와 `V` 를 들고 있으면 `T²` 로 준다.

</details>

## 다음 장

**D3. 현대적 레시피.**

어텐션만으로는 트랜스포머가 안 된다. 층을 쌓으면 훈련이 안 되기 때문이다.

D3에서 네 가지를 설치한다.

- **잔차 연결** — `x + f(x)`. 층을 건너뛰는 지름길
- **RMSNorm** — 층마다 분산을 1 근처로 되돌린다
- **Pre-Norm** — 정규화를 층 **앞**에 둔다. 뒤에 두는 것과 뭐가 다른가
- **QK-Norm** — `Q` 와 `K` 를 정규화한다. `√d` 로도 모자랄 때

그리고 여기서 **"왜?"를 답하지 않는다.**

넷 다 **훈련 안정성 장치**다. 그런데 지금은 훈련을 안 하고 있으므로 무엇이 불안정한지 볼 수가 없다. D6~D7에서 그래디언트가 실제로 폭주해봐야 이유가 들어온다.

**D3은 설치, D7이 납득.** 그 순서를 지키는 것이 이 교재의 선택이다. 이유를 모른 채 설치하는 것이 불편하겠지만, 이유를 먼저 설명해봐야 와닿지 않는다.
