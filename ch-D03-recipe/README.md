## 0. 설치와 납득

이 장에서 네 가지를 설치한다.

| 것 | 하는 일 |
|---|---|
| **잔차 연결** | `x + f(x)`. 층을 건너뛰는 지름길 |
| **RMSNorm** | 층마다 크기를 1 근처로 되돌린다 |
| **Pre-Norm** | 정규화를 층 **앞**에 둔다 |
| **QK-Norm** | `Q`, `K` 를 따로 정규화한다 |

넷 다 **훈련 안정성 장치**다. 그런데 우리는 아직 훈련을 안 하고 있다.

그래서 이 장은 **"왜?"를 절반만 답한다.** 순전파에서 눈에 보이는 효과 — 신호가 사라지는가, 분포가 무너지는가 — 는 여기서 재고, 그래디언트가 실제로 폭주하는 모습은 D6~D7에서 본다.

**D3은 설치, D7이 납득.**

다만 "이유는 나중에"로 끝내지는 않는다. 순전파만으로도 **숫자가 확실히 갈린다.**

```
[D3-3] 층을 쌓으면 신호가 어떻게 되는가

      깊이            맨몸          잔차만       Post-Norm        Pre-Norm
         1       1.574e-02       5.926e-01       1.000e+00       6.293e-01
        16       2.696e-21       1.065e+00       1.000e+00       1.264e+00
```

**맨몸으로 16층을 쌓으면 신호가 `1e-21` 이 된다.** 입력이 무엇이었든 출력은 0이다.

## 1. RMSNorm

```
RMS = sqrt(평균(x²))
결과 = x / RMS × 이득
```

```
  x = (3, 4, 0, 0)
  RMS = sqrt((9+16)/4) = 2.5000
  결과 = (1.2000, 1.6000, 0.0000, 0.0000)
  손계산 (1.2, 1.6, 0, 0)

  정규화한 것의 RMS = 1.000000024
  입력을 100배로 키우면 = (1.2000, 1.6000, ...)
```

**입력을 100배로 키워도 결과가 같다.** 이게 정규화가 하는 일이다 — 크기 정보를 버리고 **방향만 남긴다.**

### LayerNorm 과 무엇이 다른가

| | LayerNorm | RMSNorm |
|---|---|---|
| 평균 빼기 | 한다 | **안 한다** |
| 나누는 것 | 표준편차 | **RMS** |
| 치우침(bias) | 있다 | **없다** |

평균 빼기와 치우침을 없앴는데 성능이 거의 같다는 것이 2019년에 밝혀졌다. 그 뒤로 큰 모델은 대개 RMSNorm을 쓴다. **계산이 적고 구현도 짧다.**

없애도 되는 이유를 짐작해보면, 뒤따르는 선형층이 어차피 평균 이동을 표현할 수 있기 때문이다. 정규화가 굳이 할 필요가 없다.

### `Epsilon` 이 하는 일

```cpp
double Scale = 1.0 / std::sqrt(SquareSum / Last + Epsilon);
```

```
  전부 0 인 줄도 무사한가 = 예 (Epsilon 덕분)
```

값이 전부 0인 줄이 있으면 `RMS = 0` 이고 `1/0` 이 된다. `Epsilon` 을 더하면 무한대 대신 아주 큰 유한한 수가 나오고, 곱하면 0이므로 결과가 0이다. **죽지 않는다.**

패딩 위치나 초기화 직후에 실제로 생긴다. `1e-6` 은 정상적인 값에는 영향을 안 주면서 이 경우만 막는다.

## 2. SiLU

```
       x        relu        silu
   -4.00    0.000000   -0.071945
   -1.00    0.000000   -0.268941
    0.00    0.000000    0.000000
    1.00    1.000000    0.731059
    4.00    4.000000    3.928055
```

`SiLU(x) = x · sigmoid(x)`. Swish라고도 부른다.

양수 쪽은 `relu` 와 거의 같고, **음수 쪽이 완전히 0이 아니다.** `-1` 에서 `-0.269` 다.

왜 그게 좋은가. `relu` 는 음수 입력에서 미분이 정확히 0이라, 한 번 음수로 가면 그 뉴런에 그래디언트가 영원히 안 온다(**죽은 ReLU**). SiLU는 조금이라도 흐른다.

### `sigmoid` 를 안전하게

```cpp
if (V >= 0.0) return 1.0 / (1.0 + exp(-V));
double E = exp(V);
return E / (1.0 + E);
```

`x` 가 크게 음수면 `exp(-x)` 가 넘친다. 부호에 따라 식을 바꾸면 **지수가 항상 0 이하**가 되어 안 넘친다.

C1의 softmax에서 최댓값을 뺀 것, B2의 `LogAdd` 에서 큰 쪽을 뽑아낸 것과 **같은 요령**이다. 세 번째 등장이다.

```cpp
CHECK(std::isfinite((double)Silu(Real(1000))));
CHECK(std::isfinite((double)Silu(Real(-1000))));
```

## 3. 잔차 연결

층을 그냥 쌓으면 신호가 사라진다.

```
      깊이            맨몸          잔차만       Post-Norm        Pre-Norm
         1       1.574e-02       5.926e-01       1.000e+00       6.293e-01
         2       8.162e-04       6.183e-01       1.000e+00       6.953e-01
         4       3.783e-06       6.598e-01       1.000e+00       7.942e-01
         8       3.933e-11       7.621e-01       1.000e+00       9.649e-01
        16       2.696e-21       1.065e+00       1.000e+00       1.264e+00
```

**맨몸은 층마다 약 40분의 1로 줄어든다.** 16층이면 `1e-21`.

이유는 초기화에 있다. 가중치를 `sqrt(1/입력수)` 범위로 채우면 **출력의 크기가 입력보다 작아진다.** 층을 지날 때마다 곱해지니 지수적으로 사라진다.

그리고 이건 **역방향에서도 똑같이 일어난다.** 그래디언트가 앞쪽 층까지 못 간다. 2015년 이전에 깊은 신경망을 못 만든 이유가 이것이다.

```cpp
FTensor Result = Config.bResidual ? (std::move(FeedOut) + FeedInput) : std::move(FeedOut);
```

**한 줄 더하기다.** `x + f(x)` 로 두면 `f` 가 아무리 작아져도 `x` 는 그대로 통과한다. 층을 100개 쌓아도 입력이 출력까지 닿는다.

## 4. Pre-Norm 과 Post-Norm

```
Post-Norm   x -> Norm(x + Attn(x))
Pre-Norm    x -> x + Attn(Norm(x))
```

차이는 **잔차 경로에 정규화가 끼어 있느냐**다.

- Post-Norm은 더한 **뒤에** 정규화한다. 지름길도 정규화를 통과한다
- Pre-Norm은 **안쪽만** 정규화한다. 지름길은 아무 변형 없이 이어진다

표에서 Post-Norm이 깊이와 무관하게 정확히 `1.000` 인 것이 그 증거다. 마지막이 정규화이므로 당연히 RMS가 1이다.

겉보기에는 Post-Norm이 더 안정적으로 보인다. 그런데 현대 모델은 거의 다 Pre-Norm을 쓴다. 이유는 **역방향**에 있다.

Pre-Norm에서는 입력에서 출력까지 **덧셈만 거치는 길**이 있다. 덧셈의 미분은 1이므로 그래디언트가 손실 없이 내려온다. Post-Norm은 그 길에 정규화가 있어서, 층이 깊어지면 그래디언트가 눌린다.

### 초기 상태가 항등 함수다

```
  가중치를 전부 0 으로 두면 Pre-Norm 블록은 입력을
  그대로 내보내야 한다. 최대 차이 = 0.000e+00
```

```cpp
CHECK(WorstGap < 1e-6);
```

가중치가 0이면 `Attn(Norm(x)) = 0` 이고 `x + 0 = x` 다. **블록이 아무 일도 안 한다.**

이게 왜 좋은가. 훈련 시작 시점에 모델이 **"일단 그대로 흘려보내는"** 상태이면, 층을 아무리 깊게 쌓아도 출력이 무너지지 않는다. 거기서 조금씩 배워나간다.

실제로 큰 모델들은 마지막 선형층(`Project`, `Down`)을 아주 작게 초기화하거나 0으로 두는 경우가 많다. 같은 이유다.

> 이 검사는 **단위 테스트로도 훌륭하다.** 블록의 배선이 한 군데라도 틀리면 `0.000e+00` 이 안 나온다. 잔차를 빼먹었거나, 더하는 대상을 잘못 골랐거나, 정규화 자리를 틀렸거나.

## 5. QK-Norm

D2에서 `√d` 로 나눴다. 그런데 **훈련 중에 `Q`, `K` 가중치가 커지면** 그것으로 모자란다.

```
       Q,K 가중치 크기      QK-Norm 없이      QK-Norm 켜고
                    x1            0.9767            0.8317
                    x4            0.1631            0.8317
                   x16            0.0000            0.8317
                   x64            0.0000            0.8317
```

**가중치를 16배로 키우면 엔트로피가 0이 된다.** 어텐션이 한 곳만 보고 나머지를 완전히 무시한다. 그리고 그 상태에서는 **그래디언트가 안 흐르므로 되돌아올 수도 없다.**

QK-Norm을 켜면 가중치가 64배가 되어도 **0.8317로 고정**이다.

```cpp
if (Config.bQkNorm)
{
    Q = RmsNorm(Q, QueryGain, (Real)1e-6);
    K = RmsNorm(K, KeyGain, (Real)1e-6);
}
```

`Q` 와 `K` 를 각각 정규화하면 내적의 크기가 **가중치 크기와 무관**해진다. 방향만 남기니까.

값이 0.9767이 아니라 0.8317에서 시작하는 것에 주목할 것. QK-Norm은 **공짜가 아니다** — 크기 정보를 버리므로 모델이 "이 관계는 강하다"를 점수 크기로 표현하지 못한다. 대신 `QueryGain`, `KeyGain` 이라는 학습 가능한 이득으로 일부 되찾는다.

> 이 장치는 비교적 최근(2023년 전후)에 널리 쓰이기 시작했다. 대규모 훈련에서 손실이 갑자기 튀는 현상의 원인 중 하나가 어텐션 점수 폭주라는 것이 밝혀지면서다. **문제가 실제로 터진 뒤에 처방이 나온 것**이고, 이 순서가 흔하다.

## 6. 블록 하나

```
  모델차원 64, 헤드 4, 앞먹임 256
  가중치 49280개
  입력 (2, 8, 64) -> 출력 (2, 8, 64)
```

**입력과 출력의 모양이 같다.** 그래서 블록을 몇 개든 쌓을 수 있다.

가중치 49,280개의 내역은 이렇다.

| 것 | 개수 |
|---|---|
| `Q`, `K`, `V`, `Project` | 64×64 × 4 = 16,384 |
| `Up` (64→256), `Down` (256→64) | 16,384 × 2 = 32,768 |
| 정규화 이득 두 개 | 128 |

**앞먹임 부분이 어텐션보다 크다.** 트랜스포머 가중치의 3분의 2가 앞먹임에 있다는 것이 일반적인 사실이다.

### 인과성은 블록 전체에서 지켜져야 한다

```
  마지막 위치의 입력만 바꿨을 때
    앞쪽 출력의 변화 = 0.000e+00 (0 이어야 한다)
    마지막 출력의 변화 = 5.904e+00 (커야 한다)
```

```cpp
CHECK(EarlyGap < 1e-6);
CHECK(LateGap > 1e-3);
```

D2에서 어텐션 가중치의 우상단이 0인지 봤다. 여기서는 **블록 전체**를 두드려본다.

마지막 위치의 입력만 바꾸고, 앞쪽 출력이 **하나도** 안 바뀌는지 확인한다. 어딘가에서 뒤를 훔쳐보고 있으면 여기가 깨진다.

이 검사가 특히 값진 이유는, **마스크 말고 다른 경로로도 정보가 샐 수 있기 때문**이다. 예를 들어 정규화를 위치 축을 따라 걸면(실수하기 쉽다) 뒤쪽 값이 앞쪽 통계에 섞여 들어간다. 어텐션 가중치만 봐서는 안 잡힌다.

## 정리

만든 것.

| 파일 | 내용 |
|---|---|
| `lib/Block.hpp` · `.cpp` | RMSNorm, SiLU, `FDense`, `FBlock` |

`FDense` 는 C1의 `FLinear` 와 다르다. **`(..., In)` 모양이면 무엇이든 받아 마지막 축만 바꾼다.** 앞쪽 축이 배치든 위치든 신경 쓰지 않는다 — C5에서 "배치를 넣을 자리가 없다"고 했던 문제가 여기서 풀린다.

알아둘 것.

- **맨몸으로 16층을 쌓으면 신호가 `1e-21` 이 된다.** 잔차가 필요한 이유
- **정규화는 크기를 버리고 방향만 남긴다**
- **Pre-Norm 은 초기 상태가 항등 함수다.** 그 검사가 곧 배선 검사
- **`Epsilon` 은 0인 줄을 살린다**
- **지수 계산은 부호에 따라 식을 바꾼다.** 세 번째 등장
- **QK-Norm 은 가중치가 커져도 분포를 지킨다.** 대신 크기 정보를 버린다
- **가중치의 3분의 2가 앞먹임에 있다**
- **인과성은 블록 전체에서 두드려본다.** 마스크 말고 다른 경로로도 샌다

쓴 문법.

- D1의 `Reshaped` 로 임의 차원을 2차원으로 눕히기
- `std::move` 로 텐서를 넘겨 복사 없이 더하기
- 설정 구조체(`FBlockConfig`)로 변형을 한 클래스에 담기

## 연습문제

**1.** `FDense::Forward` 가 `Reshaped` 를 두 번 쓴다. 이게 낭비인가?

<details>
<summary>해답</summary>

**지금 구현에서는 낭비가 맞다.** D1에서 적어둔 대로 우리 `Reshaped` 는 복사를 한다.

```cpp
FTensor Flat = X.Reshaped({ Rows, In });     // 복사 1
FTensor Product = MatMul(Flat, Weight);
return Product.Reshaped(Shape);              // 복사 2
```

`(2, 8, 64)` 짜리면 1,024개를 두 번 복사한다. 실제 크기에서는 무시 못 한다.

**모양만 바꾸는 것이므로 원리적으로는 공짜여야 한다.** 값이 하나도 안 움직이는데 왜 복사하는가.

고치는 방법이 둘이다.

**(가) 뷰를 지원한다.** D1 연습문제 2의 `shared_ptr` + 보폭 이야기다. 제대로 하려면 텐서 구현이 두 배로 복잡해진다.

**(나) `Reshape` 를 제자리 연산으로 만든다.**

```cpp
void FTensor::Reshape(const std::vector<size_t>& NewShape)
{
    assert(ProductOf(NewShape) == Total);
    Shape = NewShape;     // 모양만 바꾼다. 값은 그대로
}
```

`Shape` 벡터만 바꾸면 끝이다. 원본을 고치므로 `const` 함수가 아니게 되지만, `FDense::Forward` 에서는 어차피 지역 복사본을 쓰므로 문제없다.

**(나)가 훨씬 싸다.** 이 교재가 (가)를 안 한 것은 D1에서 적은 이유이고, (나)를 안 한 것은 `Reshaped` 가 값을 돌려주는 모양이 읽기 좋아서다.

D4에서 KV 캐시를 만들 때 이 복사가 실제로 아파온다. 그때 고친다. **아직 아픈지 모르는 것을 미리 고치지 않는 것**도 C5에서 배운 태도다.

</details>

**2.** Post-Norm 이 항상 RMS 1.000 인데, 그게 왜 좋지 않은가?

<details>
<summary>해답</summary>

**순전파에서는 좋다. 역전파에서 나쁘다.**

Post-Norm의 출력은 마지막 연산이 정규화이므로 크기가 정확히 1이다. 신호가 커지지도 사라지지도 않는다. 겉보기에 완벽하다.

문제는 그래디언트다. 잔차 경로 `x → x + f(x)` 의 미분은 `1 + f'` 인데, Post-Norm은 그 뒤에 정규화가 붙어 `Norm'(·)(1 + f')` 이 된다.

`Norm'` 은 대략 `1/RMS` 크기다. 층을 지날 때마다 이 인자가 곱해지고, **깊어지면 그래디언트가 눌린다.**

실제로 원논문(2017)은 Post-Norm이었다. 그때는 6층이라 문제가 안 됐다. 층이 수십 개로 늘어나면서 Post-Norm 모델이 **훈련을 시작조차 못 하는** 일이 생겼고, 그래서 **학습률 워밍업**이라는 처방이 나왔다 — 초반에 아주 작은 학습률로 시작해 서서히 올리는 것.

Pre-Norm으로 바꾸니 워밍업 없이도 훈련이 됐다. 그게 2019년쯤의 발견이고, 그 뒤로 거의 다 Pre-Norm이다.

**표에서 "완벽해 보이는" 열이 실제로는 나쁜 선택**이라는 것이 이 절의 교훈이다. 순전파의 숫자만 보고 판단하면 틀린다. D7에서 실제로 훈련해봐야 갈린다.

</details>

**3.** 블록을 쌓을 때 마지막에 정규화를 한 번 더 하는 모델이 많다. 왜인가?

<details>
<summary>해답</summary>

**Pre-Norm 은 마지막 출력을 정규화하지 않기 때문**이다.

표를 다시 보자.

```
        16       ...       Pre-Norm  1.264e+00
```

깊이가 늘수록 Pre-Norm의 출력 크기가 커진다(0.629 → 1.264). 잔차로 계속 더하기만 하니 당연하다.

그 값이 그대로 출력층(어휘 크기만큼의 점수)으로 가면 **점수가 커지고 softmax가 뾰족해진다.** D2에서 본 그 문제다.

그래서 마지막 블록 뒤에 정규화를 하나 더 둔다.

```
x -> Block -> Block -> ... -> Block -> Norm -> 출력층
```

이걸 **final norm** 이라고 부르고, GPT 계열이 전부 갖고 있다.

D4에서 모델 전체를 조립할 때 이 줄을 넣는다. 한 줄인데 없으면 훈련 초반 손실이 엉뚱하게 크게 나온다 — C1에서 세운 "초기 손실은 `log(어휘)`" 검사가 그걸 잡아준다.

**설치할 것이 하나 더 있다는 것을 표가 알려준 셈이다.** 순전파의 숫자를 재두면 이런 것이 보인다.

</details>

## 다음 장

**D4. 추론 완성 — KV 캐시.**

조각이 다 모였다. D4에서 **돌아가는 모델**을 만든다.

```
토큰 → 임베딩 → 위치 정보 → 블록 × N → 최종 정규화 → 출력층 → softmax
```

그리고 **글자를 하나씩 뽑는다.** A5에서 바이그램으로 했던 일을 트랜스포머로 한다.

여기서 문제가 하나 나온다. 글자를 뽑을 때마다 **문맥 전체를 처음부터 다시 계산**하면, `T` 글자를 만드는 데 `T³` 이 든다. 100글자면 100만 번의 블록 통과다.

그런데 이미 계산한 `K` 와 `V` 는 **안 바뀐다.** 새 토큰이 붙어도 앞의 것들은 그대로다. 들고 있으면 매번 한 칸씩만 계산하면 된다. 그게 **KV 캐시**이고, 실제 추론 서버의 메모리 대부분을 차지하는 것이기도 하다.

검증은 **PyTorch 로짓과 대조**다. 같은 가중치를 `.npy` 로 주고받아(C4가 여기서 쓰인다) 같은 입력에 같은 출력이 나오는지 본다. 우리 구현이 "그럴듯한 것"이 아니라 **맞는 것**임을 확인하는 자리다.

그리고 D4까지 오면 **훈련을 안 할 독자는 여기서 멈춰도 완성품이 남는다.** 추론 경로가 완결된다.
