# D6. 트랜스포머 역전파

> **선행** · C2 (역전파와 gradcheck) · C++ 교재 `8.3` 함수 객체와 람다 · D2 ~ D4
> **만드는 것** · `lib/Backward`, `lib/GradCheck` 에 `GradCheckScattered` 추가
> **예제** · D6-1 ~ D6-7

---

## 0. 규칙은 하나도 안 바뀐다

C2에서 세 층짜리 신경망의 미분을 손으로 썼다. 여기서는 같은 일을 트랜스포머 한 채에 한다.

**연쇄 법칙 말고는 아무것도 새로 안 배운다.** 다만 두 가지가 처음 나온다.

1. **softmax 의 야코비안** — C2에서는 softmax 뒤에 교차 엔트로피가 바로 붙어 있어서 `p - y` 로 정리됐다. 어텐션 안의 softmax 는 그렇지 않다
2. **갈라진 길** — 잔차 연결은 같은 값을 두 길로 보낸다. 임베딩 하나가 여러 자리에 쓰이기도 한다. 그러면 그래디언트가 **여러 곳에서 와서 더해진다**

그리고 이 장의 결론은 숫자 하나다.

```
파라미터 1384개 중 300개를 골라 흔들었다.

최대 상대 오차 = 6.787e-07  (번호 284)
  역전파  -0.000004746
  수치    -0.000004746

모델 전체 gradcheck            6.787e-07   통과
```

**손으로 쓴 미분이 맞다는 증거다.** 이게 없으면 아무 말도 할 수 없다.

## 1. softmax 의 야코비안

C2에서 `Softmax → CrossEntropy` 는 `p - y` 였다. 너무 깔끔해서 오해하기 쉬운데, **그건 softmax 의 미분이 아니라 둘을 합친 것의 미분**이다.

softmax 하나만 떼면 이렇게 생겼다.

```
dP_i / dS_j = P_i (δ_ij - P_j)
```

`i` 와 `j` 가 둘 다 있다. 출력 하나가 **모든 입력**에 대해 미분값을 갖는다. 이런 것을 야코비안이라 부른다.

실제로 찍어보면 이렇다. 점수가 `(2.0, 1.0, 0.1, -0.5)` 이면 확률은 `(0.6252, 0.2300, 0.0935, 0.0513)` 이고,

```
            j=0        j=1        j=2        j=3
 i=0    +0.23433   -0.14379   -0.05846   -0.03208
 i=1    -0.14379   +0.17710   -0.02151   -0.01180
 i=2    -0.05846   -0.02151   +0.08476   -0.00480
 i=3    -0.03208   -0.01180   -0.00480   +0.04868
```

읽는 법.

- **대각선 밖이 0 이 아니다.** 점수 하나를 올리면 나머지 확률이 전부 내려간다. 합이 1 로 묶여 있으니 당연하다
- **각 줄의 합이 정확히 0 이다.** 모든 점수를 똑같이 올리면 확률은 하나도 안 변한다. D2에서 softmax 가 최댓값을 빼도 되는 이유가 이것이었다
- 대칭이다. `P_i P_j` 항이 `i`, `j` 를 맞바꿔도 같다

### 그런데 만들지 않는다

야코비안은 `(N × N)` 이다. 어텐션이면 `N` 이 문맥 길이다. 8192면 6700만 칸짜리 행렬을 **자리마다, 헤드마다** 만들어야 한다. 말이 안 된다.

식을 정리하면 안 만들어도 된다.

```
dS_j = Σ_i G_i P_i (δ_ij - P_j)
     = G_j P_j - P_j Σ_i G_i P_i
     = P_j ( G_j - Σ_i G_i P_i )
```

**안쪽 합이 `j` 에 안 걸린다.** 한 번 구해두면 끝이다. `O(N²)` 이 `O(N)` 이 된다.

```cpp
double Dot = 0.0;
for (i) Dot += P[i] * G[i];

for (i) Out[i] = P[i] * (G[i] - Dot);
```

행렬을 실제로 만들어 곱한 값과 대조하면 상대 오차 `1.976e-16` 이다. 같은 계산이다.

### 마스크는 따로 안 챙긴다

D2에서 인과 마스크는 막힌 자리를 `-1e30` 으로 눌렀다. softmax 를 지나면 그 자리가 0 이 된다.

역전파에서 그 자리를 다시 막아야 하는가. **안 해도 된다.**

```
dS_i = P_i (G_i - dot)
```

`P_i` 가 0 이면 `dS_i` 도 0 이다. **순전파에서 눌러둔 것이 역전파에서 저절로 지워진다.**

`-∞` 대신 유한한 `-1e30` 을 쓴 값이 여기서도 돌아온다. `-∞` 였으면 `exp(-∞) = 0` 까지는 같지만, 마스크가 겹쳐 한 줄이 통째로 막히면 `0/0` 이 나온다. 유한값이면 최악에도 균등 분포다.

## 2. RMSNorm — 한 칸을 흔들면 줄 전체가 움직인다

```
y_i = g_i · x_i · s,    s = 1 / sqrt( mean(x²) + ε )
```

`s` 가 `x` 전체에 걸려 있다. **`x_k` 를 흔들면 `s` 가 움직이고, 그러면 그 줄의 모든 `y` 가 같이 움직인다.**

```
ds/dx_k = -s³ x_k / N

dL/dx_k = g_k s u_k  -  (s³ x_k / N) Σ_i u_i g_i x_i
          ~~~~~~~~~     ~~~~~~~~~~~~~~~~~~~~~~~~~~~~
          제 몫          줄 전체가 얽힌 몫
```

뒤쪽 항이 없으면 gradcheck 가 통과하지 않는다. 그리고 **그 버그는 손실을 조금만 느리게 내려가게 만든다.** 조용히 틀리는 종류다.

이득 쪽은 반대로 단순하다.

```
dL/dg_i = Σ_rows ( u_i · x_i · s )
```

**모든 줄에서 더한다.** 이득은 줄마다 공유되기 때문이다. 이것이 이 장의 두 번째 주제인 "갈라진 길"의 가장 작은 예다.

## 3. 조각별로 확인한다

블록을 통째로 검사하다 틀리면 **어디가 틀렸는지 알 수가 없다.** 조각부터 하나씩 본다.

```
무엇을                    최대 상대 오차
RMSNorm  dX                    1.342e-09   통과
RMSNorm  dGain                 2.621e-10   통과
SiLU  dX                       1.553e-07   통과
FDense  dX                     3.031e-09   통과
FDense  dW                     2.355e-10   통과
FDense  dBias                  4.348e-11   통과
Attend  dQ                     5.238e-09   통과
Attend  dK                     1.426e-08   통과
Attend  dV                     6.446e-09   통과
```

검사 방법은 C2와 같다. 출력을 난수 가중치로 섞어 스칼라 하나로 줄이고, 입력을 하나씩 흔들어 중심 차분과 대조한다.

```cpp
auto Loss = [&]() { return Reduce(Attend(Q, K, V, true).Output, Weights); };
```

> **왜 `Sum` 이 아니라 난수 가중치인가.** 그냥 다 더하면 모든 원소의 가중치가 1 이라, 부호가 반대인 실수 두 개가 상쇄되어 안 보일 수 있다. 난수로 섞으면 상쇄될 확률이 사실상 0 이다.

`SiLU dX` 만 `1.553e-07` 로 다른 것보다 두 자리 나쁘다. `Sigmoid` 안의 `exp` 때문이다. 나머지는 곱셈과 덧셈뿐이다.

### 어텐션 역전파

```
O = P V         →   dV = Pᵀ U,      dP = U Vᵀ
P = softmax(S)  →   dS = SoftmaxBackward(P, dP)
S = QKᵀ/√d      →   dQ = dS K /√d,  dK = dSᵀ Q /√d
```

`dK` 에 `dSᵀ` 가 붙는 것을 놓치기 쉽다. `S` 의 `(q, k)` 칸은 `Q` 의 `q` 번째 줄과 `K` 의 `k` 번째 줄에서 나왔다. `K` 쪽으로 돌아갈 때는 축이 바뀐다.

그리고 **머리 나누기(SplitHeads)의 역은 머리 합치기(MergeHeads)** 다. 값을 새로 만드는 게 아니라 축을 도로 바꿔놓는 것뿐이다.

## 4. 갈라진 길은 더한다

블록 하나의 순전파를 다시 본다.

```
A      = Project(Merge(Attend(Split(QKV(Norm(X)))))) + X
Result = Down(SiLU(Up(Norm(A)))) + A
```

`X` 와 `A` 가 각각 **두 길로 갈라진다.**

```cpp
FTensor AfterAttentionGrad = RmsNormBackward(..., Normed1, Grad.FeedGain);

// 잔차. 지름길로 온 몫을 더한다.
AddInto(AfterAttentionGrad, Upstream);
```

`=` 가 아니라 `+=` 다. 여기서 `=` 를 쓰면 지름길로 온 그래디언트가 통째로 사라진다.

그리고 한 군데 더 있다. **Q, K, V 가 같은 `Normed` 에서 나왔다.**

```cpp
FTensor NormedGrad = DenseBackward(Block.Query, Trace.Normed, ..., Grad.Query);
AddInto(NormedGrad, DenseBackward(Block.Key,   Trace.Normed, ..., Grad.Key));
AddInto(NormedGrad, DenseBackward(Block.Value, Trace.Normed, ..., Grad.Value));
```

셋 다 더해야 한다. 규칙은 하나다.

> **순전파에서 한 값이 N 곳에 쓰였으면, 역전파에서 그 값의 그래디언트는 N 곳에서 와서 더해진다.**

`FDenseGrad` 와 `FBlockGrad` 가 `Zero()` 를 따로 두고 `DenseBackward` 가 `AddInto` 로 쌓는 것도 같은 이유다. **덮어쓰는 함수를 만들지 않는 편이 안전하다.**

블록 하나로 재보면 이렇다.

```
무엇을                    최대 상대 오차
입력  dX                       5.191e-09   통과
Query  dW                      9.811e-08   통과
Value  dW                      4.184e-08   통과
Down  dW                       3.119e-08   통과
AttentionGain                  2.853e-10   통과
FeedGain                       5.723e-09   통과
```

## 5. 임베딩 — 가장 노골적인 공유

토큰 임베딩은 갈라진 길의 극단이다. 같은 토큰이 열 자리에 나오면 그 줄이 **열 번 쓰인다.**

어휘 `0, 1, 2` 만 12자리에 돌려 넣고 그래디언트 크기를 재봤다.

```
어휘         쓰인 횟수   그래디언트 크기
0                    4          1.003677
1                    4          0.282199
2                    4          0.343112
3                    0          0.000000

안 쓰인 어휘 13개는 전부 정확히 0 이다.
```

**쓰이지 않은 가중치는 배우지 않는다.**

이게 별것 아닌 것 같지만 규모가 커지면 중요해진다. 어휘가 5만이고 한 묶음에 토큰이 4096개면, 한 걸음에서 실제로 움직이는 임베딩 줄은 많아야 4096개다. **90% 이상이 그대로 있다.** 그래서 임베딩은 희소하게 갱신하는 최적화가 따로 있다.

위치 임베딩은 더하다. `t` 번째 줄은 **배치의 모든 예제**가 쓴다. 배치가 64면 64번 더해진다.

```cpp
Grad.TokenEmbedding((size_t)Token, d) += G;
Grad.PositionEmbedding(t, d) += G;
```

`+=` 두 줄이다. `=` 로 쓰면 마지막 자리 것만 남는다. **그리고 손실은 여전히 내려간다.** gradcheck 없이는 못 잡는다.

## 6. 자취 — 훈련이 추론보다 비싼 이유

역전파는 순전파의 중간값을 먹고 돈다. `Trace.Normed` 가 없으면 `dW = Xᵀ U` 의 `X` 가 없다.

그래서 순전파 때 다 들고 있어야 한다.

```
파라미터        11072 바이트
자취            23808 바이트  (2.15 배)
그래디언트      11072 바이트  (파라미터와 같다)
```

이 작은 모델에서도 **자취가 파라미터의 두 배**다. 그리고 이 둘은 성질이 다르다.

| | 무엇에 비례하나 |
|---|---|
| 파라미터 · 그래디언트 | 모델 크기 |
| **자취** | 모델 크기 **× 배치 × 길이** |

어텐션 확률표 하나가 `(배치 × 헤드 × 길이 × 길이)` 다. 길이가 두 배면 네 배가 된다.

D4에서 KV 캐시가 긴 문맥의 비용이라고 했다. **훈련 쪽에서는 자취가 그 자리에 있다.** 그래서 실제로는 자취를 버리고 역전파 때 다시 계산하는 기법(gradient checkpointing)을 쓴다. 계산을 더 하고 메모리를 아끼는 맞바꿈이다.

여기에 옵티마이저 상태가 더 붙는다. AdamW 는 파라미터당 둘을 더 든다 — D7에서 만든다.

## 7. float 로는 판단이 안 선다

이 장의 코드는 **`USE_DOUBLE` 을 켜고 빌드해야 한다.** 왜 그런지가 이 절이다.

같은 코드, 같은 입력, `Real` 만 바꿔서 잰 값이다.

| 빌드 | 가장 나쁜 상대 오차 |
|---|---|
| `USE_DOUBLE` | **6.787e-07** |
| 기본 (`float`) | **1.470e+00** |

`1.470` 은 147% 어긋났다는 뜻이다. **역전파 코드는 한 줄도 안 바뀌었다.**

이유는 수치 미분이 뺄셈이기 때문이다.

```
( f(x+h) - f(x-h) ) / 2h
```

손실이 `2.934287` 이고 `h` 가 `1e-3` 이면, 두 손실의 차이는 `1e-9` 근처다. `float` 의 유효숫자는 7자리다. **`2.934287` 에서 7자리를 쓰고 나면 `1e-9` 자리는 애초에 없다.**

그래서 `float` 빌드는 이렇게 찍는다.

```
Query  dW                      1.130e-01   판단 불가
...
모델 전체 gradcheck            1.470e+00   판단 불가
```

**"실패"가 아니라 "판단 불가"다.** 이 구별이 중요하다.

- 실패라고 찍으면 **거짓말**이다. 역전파는 맞다
- 기준을 `1e-1` 로 풀어 "통과"라고 찍으면 **더 나쁜 거짓말**이다. 그 폭에서는 진짜 버그도 통과한다

**재는 도구가 못 재는 영역에 들어가면, 답은 다른 답이 아니라 "모른다"다.** A8에서 6-gram 이 자기 문맥에서는 절대 막히지 않는다는 걸 알았을 때 CHECK 를 고친 것과 같은 자리다.

그래서 이 교재의 `Real` 이 값을 한다.

```
추론      float 로 빌드한다. 두 배 빠르고 메모리도 절반이다
gradcheck double 로 빌드한다. 판단이 서야 하니까
```

**같은 소스에서 두 빌드가 나온다.** C2에서 `Real` 을 만들 때 적어둔 값이 여기서 전부 회수된다.

## 8. 한 걸음 내려가 보기

gradcheck 가 통과했으면 그래디언트 방향으로 조금 움직였을 때 손실이 줄어야 한다.

```
파라미터 1384개, 손실 = 2.934287
(어휘 16 짜리 균등 분포면 2.772589 이다)

한 걸음(학습률 0.1) 내려가니 손실 2.934287 -> 2.763544
```

초기 손실 `2.934` 가 균등 분포의 `ln 16 = 2.773` 보다 **높다.** 훈련 전 모델은 아무 말도 모르면서 아무 말이나 확신하고 있다. 정상이다.

한 걸음에 `2.763` 으로 내려가 균등 분포 아래로 갔다. **여기까지가 D6 이다.** 제대로 된 훈련 루프 — 옵티마이저, 스케줄, 클리핑 — 는 D7 이다.

> 주의. **손실이 내려간다는 것은 그래디언트가 맞다는 증거가 아니다.** 절반쯤 틀린 그래디언트로도 손실은 내려간다. 순서가 중요하다. gradcheck 가 먼저고, 손실 곡선은 그 다음이다.

## 정리

- 역전파에 새 규칙은 없다. **연쇄 법칙뿐이다**
- softmax 는 야코비안이지만 `(N×N)` 을 만들 필요가 없다. `dS_i = P_i (G_i - Σ P·G)` 로 `O(N)`
- 야코비안의 각 줄 합은 0. 점수를 다 같이 올려도 확률이 안 변한다는 뜻이다
- 마스크는 역전파에서 **저절로** 처리된다. `P = 0` 이면 `dS = 0`
- RMSNorm 은 `s` 가 줄 전체에 걸려 있어 **한 칸을 흔들면 줄 전체가 움직인다**. 그 항을 빼먹으면 조용히 틀린다
- 순전파에서 N 곳에 쓰인 값은 역전파에서 **N 곳에서 와서 더해진다**. 잔차, QKV 공유, 임베딩이 전부 같은 규칙
- `=` 대신 `+=`. 덮어쓰는 함수는 아예 만들지 않는 편이 안전하다
- 쓰이지 않은 임베딩 줄은 그래디언트가 **정확히 0**. 큰 어휘에서는 대부분이 그렇다
- 자취는 파라미터의 2.15배. 그리고 **배치와 길이에 비례**한다
- gradcheck: 모델 전체 **6.787e-07** (double) — 이게 이 장의 결론이다
- `float` 로는 **1.470**. 실패가 아니라 **판단 불가**다. 못 재는 것과 틀린 것은 다르다

## 연습문제

**1.** `BlockBackward` 에서 `AddInto(AfterAttentionGrad, Upstream)` 한 줄을 지우면 어떻게 되는가. gradcheck 는 무엇을 보고 잡아내는가. 그리고 **그 줄 없이도 손실이 내려가는지** 생각해 보라.

<details>
<summary>답</summary>

지우면 앞먹임의 잔차 연결이 사라진 것과 같다. `A` 로 돌아가는 그래디언트가 정규화를 지나온 몫만 남는다.

gradcheck 는 바로 잡는다. 수치 미분은 **순전파를 그대로 다시 돌리므로** 잔차가 살아 있다. 해석적 그래디언트만 한쪽을 빼먹었으니 어긋난다.

어디서 어긋나는가. 그 블록 **아래쪽 전부**다. 앞먹임 가중치는 멀쩡한데 어텐션 가중치와 그 아래 층, 임베딩이 전부 틀린다. 그래서 gradcheck 결과만 보면 원인이 어디인지 헷갈린다. **조각부터 검사하는 이유가 이것이다** (3절).

손실은 내려가는가. **대체로 내려간다.** 잔차 몫을 빼먹은 그래디언트도 진짜 그래디언트와 방향이 완전히 반대는 아니기 때문이다. 내적이 양수인 한 조금이라도 내려간다.

그래서 이 버그의 증상은 "안 배워진다"가 아니라 **"이상하게 느리게 배워진다"**이다. 데이터를 더 넣거나 학습률을 만지면서 몇 주를 보낼 수 있다. **gradcheck 는 그 몇 주를 사는 도구다.**

</details>

**2.** 5절에서 안 쓰인 어휘의 그래디언트가 "정확히 0"이라고 했다. `1e-30` 같은 아주 작은 값이 아니라 정확히 0 인 이유를 설명하라. 그리고 이 성질이 **옵티마이저에서** 왜 문제가 되는지 생각해 보라.

<details>
<summary>답</summary>

`TransformerBackward` 의 마지막 고리는 **나온 토큰만** 훑는다.

```cpp
for (b) for (t)
    Grad.TokenEmbedding(Tokens[b*Length+t], d) += G;
```

안 나온 줄은 `+=` 가 한 번도 실행되지 않는다. `Init()` 이 `Fill(0)` 으로 채워둔 값이 그대로 남는다. **계산 결과가 0 이 아니라, 계산이 아예 안 일어난 것이다.** 부동소수점 오차가 끼어들 자리가 없다.

옵티마이저에서 왜 문제가 되는가. **가중치 감쇠(weight decay)** 때문이다.

AdamW 의 갱신은 대략 이렇다.

```
w ← w - lr · (Adam 항) - lr · λ · w
                          ~~~~~~~~~ 그래디언트와 무관하다
```

뒤쪽 항은 그래디언트가 0이든 말든 **매 걸음 적용된다.** 그러면 이번 묶음에 안 나온 어휘 4만 9천 개의 임베딩이 조금씩 0 쪽으로 끌려간다. 나오지도 않았는데 벌을 받는 셈이다.

그래서 실제 구현은 **희소 갱신**을 한다. 이번에 등장한 줄만 건드린다. 관성(momentum) 쪽도 같은 문제가 있다 — 그래디언트가 0이어도 관성이 남아 있으면 계속 움직인다.

이 교재의 D7 은 조밀 갱신으로 간다. 모델이 작아서 차이가 안 나기 때문이다. **다만 큰 어휘에서는 다르다는 것을 알고 넘어가는 것과 모르는 것은 다르다.**

</details>

**3.** 7절에서 `float` 빌드의 상대 오차가 `1.470` 이었다. 그런데 `h` 를 키우면(예: `1e-3` → `1e-1`) 뺄셈의 자릿수 손실이 줄어든다. 그러면 `float` 로도 gradcheck 를 할 수 있는가? 왜 그렇지 않은지 설명하라.

<details>
<summary>답</summary>

없다. **두 오차가 반대 방향으로 움직이기 때문이다.**

중심 차분의 오차는 두 가지로 되어 있다.

```
자름 오차(truncation)   ~ f''' · h² / 6      h 가 크면 커진다
반올림 오차(roundoff)   ~ ε · |f| / h        h 가 작으면 커진다
```

`h` 를 키우면 반올림 오차는 줄지만 자름 오차가 커진다. 총 오차가 가장 작아지는 `h` 가 있고, 그 최솟값이 얼마냐가 정밀도로 정해진다.

대략 `h* ~ ε^(1/3)` 이고 그때의 오차는 `ε^(2/3)` 쯤이다.

| | `ε` | 최적 `h` | 그때 오차 |
|---|---|---|---|
| `float` | 1.2e-07 | ~5e-03 | **~2e-05** |
| `double` | 2.2e-16 | ~6e-06 | **~4e-11** |

`float` 의 한계가 `1e-05` 근처다. 우리가 잡고 싶은 버그 중에는 **그보다 작은 것도 있다.** 5절의 `+=` 를 `=` 로 바꾼 버그는 한 토큰이 두 번 나올 때만 차이가 나므로, 묶음에 따라 상대 오차가 `1e-04` 밖에 안 될 수 있다.

그리고 더 근본적인 문제가 있다. **`f` 자체가 `float` 로 계산된다.** `h` 를 아무리 잘 골라도 손실값 `2.934287` 이 이미 7자리에서 잘려 있다. 흔들기 폭을 바꾸는 것으로는 이걸 못 고친다.

정리하면, `h` 를 조율해서 `float` gradcheck 의 오차를 `1.470` 에서 `1e-04` 정도까지는 내릴 수 있다. **그래도 `double` 의 `1e-07` 에는 세 자리 못 미친다.** 판단 기준을 그만큼 느슨하게 잡아야 하고, 그 폭에서 통과하는 버그가 생긴다.

`USE_DOUBLE` 한 줄이 더 싸다.

</details>

## 다음 장

**D7. 훈련 루프.**

그래디언트가 맞다는 것을 확인했다. 이제 그걸로 실제로 배우게 만든다.

D6의 마지막에서 한 것은 이것이다.

```cpp
w = w - 0.1 * g;
```

이것만으로도 손실은 내려간다. 그런데 실제로 훈련을 돌려보면 세 가지가 필요해진다.

1. **AdamW** — 파라미터마다 학습률을 다르게 가져간다. 그러려면 파라미터당 상태를 둘 더 들어야 한다
2. **그래디언트 클리핑** — 어쩌다 한 번 튀는 묶음이 모델을 통째로 망가뜨린다. 크기를 잘라둔다
3. **학습률 스케줄** — 처음엔 천천히(워밍업), 나중엔 줄인다

**D3에서 설치만 하고 넘어간 안정성 장치들이 여기서 납득된다.** 잔차 연결과 정규화를 껐을 때 무슨 일이 일어나는지, 이번엔 손실 곡선으로 본다.

검증은 **손실 곡선 대조**다. 같은 초기값·같은 데이터로 NumPy 참조 구현과 나란히 돌려, 스텝마다 손실이 맞는지 본다.
