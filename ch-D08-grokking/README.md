# D8. 그로킹 재현

> **선행** · D6 (gradcheck) · D7 (훈련 루프) 전체
> **만드는 것** · 없다. D6과 D7이 만든 것만 쓴다
> **예제** · D8-1 ~ D8-5

---

## 0. 외우고 나서 한참 뒤에 이해한다

D파트의 마지막이다. 새로 만드는 것이 없다. **이미 만든 것으로 이상한 것 하나를 본다.**

작은 모델에 작은 규칙 하나를 외우게 한다. `(a + b) mod 37` 이다.

```
122걸음     훈련 정확도 100%. 외웠다
            검증 정확도 19%. 안 본 것은 못 맞힌다

            ... 그리고 5000걸음 넘게 아무 일도 안 일어난다 ...

5400걸음    검증 정확도가 90% 를 넘는다
6200걸음    99%
```

**외우고 5278걸음 뒤에 이해했다.**

이 현상에 **그로킹**(grokking)이라는 이름이 붙었다. 2022년이다. 트랜스포머가 2017년이니 5년이 걸렸다.

왜 그렇게 오래 걸렸는가. **아무도 그렇게 오래 안 봤기 때문이다.** 122걸음에서 훈련 곡선은 이미 바닥이고, 검증 곡선은 올라가고 있다. 누가 봐도 과적합이고, 끌 때다.

그래서 이 장은 **끄지 않는 법**에 관한 장이다.

---

## 1. 문제

```
입력  [a, b, =]     세 자리
정답  (a + b) % 37  마지막 자리에서만 채점한다
```

어휘는 `0 ~ 36` 과 `=` 하나, 모두 38개다. 쌍은 `37 × 37 = 1369` 개.

```
그중 35% 인 479 개로만 훈련하고,
나머지 890 개는 한 번도 안 보여준다.
```

**외우기만 하면 훈련 정확도는 100% 가 된다.** 479개를 통째로 기억하면 된다. 파라미터가 38016개니 넉넉하다.

**안 본 890개를 맞히려면 규칙을 알아야 한다.** 외운 것으로는 안 된다.

두 정확도의 차이가 곧 "외웠는가 이해했는가"다. 이 과제가 널리 쓰이는 이유가 그것이다 — **답이 무엇인지를 우리가 미리 안다.**

### 왜 소수인가

`37` 은 소수다. 합성수면 약수 구조에 기대는 부분적인 해답이 생겨 "외움"과 "이해" 사이가 흐려진다. 소수면 그런 지름길이 없다.

## 2. 마지막 자리만 채점한다

```cpp
double LastLoss(const FTensor& Logits, const uint32_t* Answers)
{
    const size_t Last = Logits.Size(1) - 1;   // 세 자리 중 마지막
    ...
}
```

D7까지는 모든 자리를 채점했다. 여기서는 마지막 하나만 본다.

이유는 간단하다. **`a` 만 보고 `b` 를 맞힐 수는 없다.** 인과 마스크 때문에 첫 자리는 `a` 밖에 못 봤고, 답은 `a` 와 `b` 를 둘 다 봐야 나온다.

앞의 두 자리까지 손실에 넣으면 **알 수 없는 것을 못 맞혔다고 벌하는 것**이다. 그 벌은 줄일 방법이 없으므로 손실에 상수처럼 깔리고, 우리가 보고 싶은 신호를 묻는다.

역전파 쪽도 같이 바꾼다.

```cpp
FTensor Result(Logits.GetShape());
Result.Fill(Real(0));          // 안 쓰는 자리는 0
```

**쓰지 않는 자리의 상류 그래디언트를 0 으로 둔다.** 그러면 D6의 역전파가 알아서 그 자리를 무시한다. 코드를 고칠 필요가 없다.

> 이것이 **손실 마스킹**이다. E1에서 임의의 자리로 일반화한다. 채팅 모델은 "사용자가 쓴 부분은 채점하지 않고 모델이 쓸 부분만 채점"해야 하는데, 그게 똑같은 일이다.

## 3. 아주 작은 모델, 아주 센 가중치 감쇠

```
층 1, 모델차원 64, 헤드 4, 앞먹임 128
파라미터 38016개

학습률 1e-03, 가중치 감쇠 1.0, 묶음 = 훈련 집합 전체
```

**감쇠 `1.0` 이 핵심이다.** D7에서 쓴 값은 `0.01` 이었다. 100배다.

왜 이렇게 세게 거는가.

```
외운 해답   무겁다. 쌍마다 따로 기억해야 하니 가중치를 많이 쓴다
규칙        가볍다. (a+b) mod p 는 구조가 있다
```

가중치 감쇠는 **무거운 쪽을 계속 밀어낸다.** 그리고 훈련 손실이 이미 0 이면 그래디언트가 거의 없으므로, **미는 힘만 남는다.**

```cpp
W -= Use * M / (std::sqrt(V) + Config.Epsilon);   // 훈련 손실이 0이면 거의 0
W -= Use * Config.WeightDecay * (*Parameters[i]); // 이건 계속 작동한다
```

D7-2에서 "AdamW 의 W 는 감쇠를 갱신 식에서 분리한 것"이라고 했다. **그 분리가 여기서 값을 한다.** 섞여 있었으면 그래디언트가 0인 구간에서 감쇠도 함께 죽는다.

묶음은 훈련 집합 전체다. 479개를 매 걸음 통째로 쓴다. 미니배치의 잡음을 없애 곡선을 깨끗하게 보려는 것이다.

여기서 끄면 이 장은 없다.


## 5. 흔들림에 대하여

곡선에 이상한 자리가 몇 군데 있다.

```
1800      0.0169      5.5712    100%     26%
3800      0.0243      3.8346    100%     36%
5200      0.0219      1.6218    100%     58%
6000      0.0491      0.6832     99%     82%
```

훈련 손실이 갑자기 100배로 튀고 검증 정확도가 떨어졌다가, 다음 보고 지점에서 돌아온다.

**버그가 아니다.** 가중치 감쇠가 계속 미는 힘과 손실이 되미는 힘이 맞서는 중이라, 어느 순간 감쇠가 조금 이기면 해답이 잠깐 무너진다. 그러면 손실이 커지고, 커진 그래디언트가 도로 밀어 올린다.

**이걸 버그로 의심하지 않으려면 근거가 있어야 한다.** 그 근거가 D6과 D7이다.

> 흔들림은 학습률을 줄이면 잦아든다. 그런데 줄이면 그로킹까지 더 오래 걸린다. 이 교재는 5분 안에 끝나는 쪽을 골랐다.

## 6. 이 장이 D파트의 마지막인 이유

그로킹을 **관측**하려면 세 가지가 필요했다.

**1. 오래 본다.** 322걸음에서 껐으면 아무것도 못 봤다. 그 지점에서 곡선은 완전히 평평하다.

**2. 훈련과 검증을 따로 본다.** 훈련 곡선만 그리면 122걸음 이후가 그냥 직선이다. 검증을 따로 재지 않으면 **볼 것 자체가 없다.**

**3. 버그가 아니라는 확신.** 손실이 5000걸음 동안 안 움직이면 보통은 코드를 의심한다. 그리고 그 의심은 대개 옳다.

**세 번째가 이 교재의 값이 회수되는 자리다.**

```
D6   gradcheck  모델 전체 최대 상대 오차 6.787e-07
D7   곡선 대조   NumPy 참조와 30걸음 최대 차이 6.661e-15
```

이 둘이 통과했다. 그래서 **"안 움직이는 것이 원래 이런 것"이라고 말할 수 있다.**

검증 도구가 없으면 이 현상은 관측되지 않는다. 관측되기 전에 꺼진다. 5년이 걸린 이유가 그것이기도 하다.

> 이 장에서 새로 만든 코드가 없다는 것이 요점이다. D6과 D7이 **정확히 맞다고 보증된 도구**를 만들어놨기 때문에, 이 장은 그걸 쓰기만 하면 된다. **도구를 먼저 맞춰놓는 값이 여기서 나온다.**

## 7. 8000걸음에 5분

```
8000 걸음에 306.8초
```

한 걸음에 38ms다. 479개 예제를 매 걸음 통째로 순전파·역전파한다.

`/openmp` 를 켜고 빌드하면 빨라진다. 그리고 **켜든 안 켜든 숫자는 같다.** D8을 위해 `MatMul` 을 병렬화하면서 나눈 축이 **출력 줄**이기 때문이다.

```cpp
#pragma omp parallel for schedule(static) if (Work > 200000)
for (int Flat = 0; Flat < Rows; Flat++)
{
    // 한 줄의 합은 한 스레드가 끝까지 맡는다
}
```

한 줄의 덧셈을 여러 스레드로 쪼개면 **더하는 순서가 스레드 수에 따라 달라진다.** 그러면 D7의 `6.661e-15` 가 깨진다. 줄 단위로 나누면 그 문제가 없다.

**병렬화를 하면서 결정성을 지키는 법**이 이것이다. 성능을 위해 재현성을 파는 일은 흔한데, 여기서는 팔 필요가 없었다.

## 정리

- `(a+b) mod 37`, 35% 만 보여주고 나머지는 숨긴다. **외움과 이해가 숫자로 갈린다**
- 마지막 자리만 채점한다. 안 쓰는 자리는 **상류 그래디언트를 0 으로** 두면 된다 — 손실 마스킹의 가장 단순한 판
- 가중치 감쇠 **1.0** (D7의 100배). 훈련 손실이 0이면 **미는 힘만 남는다**
- AdamW 의 W(분리된 감쇠)가 여기서 값을 한다. 섞여 있으면 그래디언트가 0인 구간에서 같이 죽는다
- **122걸음에 외우고, 5400걸음에 이해한다.** 사이가 5278걸음
- 그 사이 검증 손실은 **올라간다**. 교과서적인 조기 종료 조건이 걸린다
- 흔들림(손실이 100배 튀는 자리)은 버그가 아니라 감쇠와 손실이 맞서는 자리
- 관측에 필요한 것 = **오래 보기 + 따로 보기 + 버그가 아니라는 확신**
- 세 번째가 D6·D7이 사준 것이다. **이 장에 새 코드가 없다는 것이 요점**
- 병렬화는 **출력 줄 단위로만**. 그래야 결과가 스레드 수에 안 흔들린다

## 연습문제

**1.** 2구간(200~3000걸음)에서 검증 손실은 올라가는데 검증 **정확도**는 31%에서 35%로 조금씩 오른다. 손실과 정확도가 반대로 움직이는 것이 어떻게 가능한가.

<details>
<summary>답</summary>

둘이 재는 것이 다르다.

- **정확도**는 1등이 맞았는지만 본다. 점수가 얼마나 확신에 차 있는지는 안 본다
- **손실**은 정답에 준 확률의 로그다. 틀렸을 때 **얼마나 확신하며 틀렸는지**가 그대로 들어간다

2구간에서 모델은 외운 것을 점점 더 **강하게** 외운다. 훈련 손실이 `0.1` 에서 `0.0003` 으로 내려가는 것이 그 증거다. 이미 다 맞히고 있으니 남은 일은 확신을 키우는 것뿐이다.

그 확신이 안 본 쌍에도 적용된다. 틀린 답을 **더 세게** 말하게 된다. 그래서 검증 손실이 올라간다.

정확도가 조금씩 오르는 것은 그 와중에도 규칙의 조각이 쌓이고 있다는 뜻이다. 다만 아직 1등을 뒤집을 만큼은 아니다.

**실무적 함의.** 조기 종료를 검증 **손실**로 걸면 이 실험은 1600걸음쯤에서 멈춘다. 검증 **정확도**로 걸면 계속 간다 — 정확도는 내려가지 않으니까. 무엇으로 멈출지가 무엇을 볼 수 있는지를 정한다.

</details>

<details>
<summary>답</summary>

**`0.0` 이면 그로킹이 안 온다.**

훈련 손실이 0에 닿는 순간 그래디언트가 거의 사라진다. 갱신을 미는 힘이 아무것도 없으니 가중치가 그 자리에 머문다. 외운 해답 그대로 영원히 간다. 2구간이 끝나지 않는 것이다.

**그로킹의 동력은 손실이 아니라 감쇠다.** 이것이 이 장의 숨은 요점이다. 보통 우리는 "손실이 모델을 움직인다"고 생각하는데, 여기서는 손실이 다 끝난 뒤에 감쇠가 움직인다.

**`10.0` 이면 아무것도 못 배운다.**

감쇠가 너무 세면 손실이 되미는 힘보다 크다. 가중치가 계속 0 쪽으로 끌려가 외우지도 못한다. 훈련 정확도가 100%에 못 간다.

**그래서 감쇠는 "적당히 세야" 한다.**

```
너무 약하면   외운 채로 머문다      (그로킹 안 옴)
적당하면      외운 뒤 밀려서 이해한다 (그로킹)
너무 세면     외우지도 못한다       (학습 실패)
```

세 구간이 있고 가운데가 좁다. 그로킹을 재현하려는 사람들이 하이퍼파라미터를 한참 만지는 이유다. 그리고 **이 좁은 창이 존재한다는 것 자체가 현상의 설명**이기도 하다 — 무거운 해답과 가벼운 해답이 둘 다 훈련 데이터를 설명할 때, 감쇠가 어느 쪽을 고를지를 정한다.

</details>

**3.** 이 실험에서 훈련 비율을 35%가 아니라 90%로 올리면 그로킹 간격이 어떻게 될 것 같은가. 0%에 가깝게 내리면? 그리고 이 관계가 **실제 LLM 훈련**에 대해 무엇을 시사하는가.

<details>
<summary>답</summary>

**90%로 올리면 간격이 줄거나 사라진다.**

데이터가 많으면 외우는 쪽이 비싸진다. 1232개를 따로 기억하는 것보다 규칙 하나를 배우는 게 싸다. 그러면 처음부터 규칙 쪽으로 간다. 훈련 정확도와 검증 정확도가 **거의 같이** 올라간다. 볼 것이 없다.

**아주 낮추면 그로킹이 안 온다.**

예를 들어 5%면 68개뿐이다. `(a+b) mod 37` 을 결정하기에 정보가 모자란다. 68개를 설명하는 "가벼운" 오답이 여럿 있고, 감쇠는 그중 아무거나 고른다. 검증 정확도가 안 오른다.

**그래서 여기도 창이 있다.** 외우기가 가능할 만큼은 적고, 규칙이 유일하게 결정될 만큼은 많아야 한다.

**실제 LLM 에 대한 시사.**

큰 모델의 훈련 데이터는 조 단위 토큰이다. 위 그림에서 "90%" 쪽 끝이다. 외우는 것이 애초에 불가능하니, **처음부터 일반화 쪽으로 간다.** 그래서 실무에서 이렇게 극적인 그로킹을 잘 안 본다.

그런데 **부분적으로는 늘 일어나고 있다.** 자주 안 나오는 패턴, 좁은 영역의 지식은 여전히 "외울 만한" 양이다. 그 부분에서는 이 실험과 같은 일이 벌어진다 — 한동안 외운 채로 있다가, 더 훈련하면 어느 순간 일반화된다.

그리고 이것이 **큰 모델을 오래 훈련하는 이유**의 하나이기도 하다. 손실 곡선이 평평해 보여도 안에서는 재편이 일어나고 있을 수 있다. 다만 **평평해 보이는 것이 늘 그런 것은 아니다.** 어느 쪽인지 판단하는 것이 실제로 어려운 일이고, E3에서 다룰 주제다.

</details>

## 다음 장

**E1. 채팅 템플릿과 손실 마스킹.**

D파트가 끝났다. 트랜스포머를 만들고, 돌리고, 작게 만들고, 훈련시키고, 이상한 것까지 봤다.

E파트는 **쓸 수 있는 물건으로 만드는 일**이다.

지금 우리 모델은 글을 **이어 쓴다.** 그것뿐이다. "한국"을 주면 "한국의 대통령..."이 나온다. 대화가 아니다.

대화로 만들려면 두 가지가 필요하다.

**① 틀.** 누가 말하는 차례인지를 토큰으로 표시한다.

```
<|system|>너는 도움이 되는 비서다<|end|>
<|user|>안녕<|end|>
<|assistant|>안녕하세요<|end|>
```

**② 마스킹.** 사용자가 쓴 부분은 **채점하지 않는다.** 모델이 쓸 부분만 채점한다. 사용자의 말을 흉내내게 만들면 안 되기 때문이다.

D8에서 마지막 자리만 채점한 그 일을, 임의의 자리로 일반화한다.

검증은 **마스킹된 위치의 그래디언트가 정확히 0 인지**다. D6에서 "안 쓰인 임베딩의 그래디언트는 정확히 0"을 확인한 것과 같은 종류의 검사다.
